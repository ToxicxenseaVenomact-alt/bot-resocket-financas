# Smart Finance Control 🤖📊

A Telegram bot that acts as a personal finance assistant: send a natural-language message ("spent 50 on groceries", "create a spreadsheet Budget2026 with the 12 months") and it interprets the intent with an LLM, organizes everything into a Google Sheets spreadsheet on **the user's own Google Drive**, and keeps context between messages (last spreadsheet/tab used, recent history, reversible actions via `/undo`).

## How it works

```
Telegram ──► Next.js (webhook + orchestration + Google OAuth)
                 │
                 ├── Prisma + MongoDB (users, tokens, context memory)
                 ├── Google Sheets/Drive API (the user's own spreadsheet)
                 └── Python/FastAPI service (api.py)
                          └── Groq (LLM) interprets the text and decides the action
```

- **`src/app/api/telegram`** — the bot's webhook (Telegraf). Receives the message, resolves which spreadsheet/tab to use (with fuzzy name matching via Levenshtein distance, similar to a spell-checker), and delegates transaction interpretation to the Python service.
- **`api.py`** — FastAPI microservice that talks to Groq (Llama 3.3 model) to turn text/receipts into a structured action on the spreadsheet (insert row, update cell, create tab, generate chart, delete with confirmation, etc.).
- **Google login (NextAuth)** — each user authorizes the bot to access their own Google Drive/Sheets; the bot never uses a spreadsheet shared across users.
- **Prisma + MongoDB** — stores the `telegramId ↔ Google account` link, the active spreadsheet/tab, and a short history of recent interactions, used to restore context and resume interrupted operations (e.g. the server went down mid-reply).

## Stack

Next.js 16 (App Router) · TypeScript · Telegraf · NextAuth · Prisma/MongoDB · FastAPI · Groq · Google Sheets/Drive API

## Security

- The Telegram webhook only accepts updates carrying the correct `secret_token` (prevents anyone from forging messages on behalf of another user).
- The `telegramId ↔ Google account` link is established through a signed (HMAC) "state" generated by the bot itself, never from a loose value sent by the client — this prevents anyone from swapping the Google account linked to someone else.
- The Python service's internal routes (`api.py`) require a shared secret (`INTERNAL_API_SECRET`), since they perform real actions on users' spreadsheets and consume paid Groq quota.
- No real secret is ever committed — only `.env.example`, with no values.
